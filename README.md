# CardCollection

Мобильное приложение для учёта коллекционных карточек по манхве. Пользователь регистрируется, смотрит каталог тайтлов, открывает коллекции (сезоны) каждого тайтла и отмечает, какие карточки у него есть и сколько копий. На вкладке «Мои коллекции» видно прогресс сбора по каждому тайтлу. Администратор пополняет каталог прямо из приложения: добавляет тайтлы, коллекции и загружает изображения карточек.

## Возможности

### Каталог и мои коллекции
- Три вкладки: **Catalog** (все тайтлы с поиском), **My collections** (тайтлы, в которых у пользователя есть карточки) и **Profile**.
- У каждой вкладки свой стек навигации: переходы внутри одной вкладки не сбрасывают другую.
- «Мои коллекции» показывают прогресс сбора: `собрано / всего` карточек, полоса прогресса и процент. Внутри можно переключать «только мои / все».
- Страница тайтла со списком коллекций, отсортированных по дате выхода (`releaseDate`). Если шапка тайтла не загрузилась, ошибка показывается на её месте, а список под ней продолжает работать.
- Сетка карточек коллекции, отсортированная по номеру. По тапу на карточку открывается модальное окно.
- Заголовки экранов берутся из загруженных данных, в параметрах маршрута передаются только id. Поэтому экран можно открыть по прямой ссылке.
- Pull-to-refresh во всех списках (хук `useRefresh`). Если сети нет, вместо запроса показывается предупреждение.

### Учёт коллекции
- Добавление и удаление своих копий карточки со счётчиком количества.
- Клиент передаёт только номер карточки: `POST /me/cards/:cardId` (+1 копия) и `DELETE /me/cards/:cardId` (−1 копия). Всё остальное сервер вычисляет сам: владельца берёт из токена, коллекцию из карточки, тайтл из коллекции, а количество из своей базы. Поэтому подделать запись нельзя: нельзя добавить несуществующую или чужую карточку, нельзя задать произвольный `count`, и у одной карточки не бывает двух строк.
- `GET /userCards` отдаёт только записи текущего пользователя, запись в `/userCards` напрямую запрещена (`405`).

### Аутентификация
- Регистрация (логин, имя, пароль с повтором) и вход. Сервер выдаёт JWT access-токен, после регистрации пользователь сразу залогинен.
- Логин без учёта регистра и пробелов по краям: `Dima` и `dima` — один аккаунт.
- Ошибки сервера (`400`, логин занят `409`) показываются под нужным полем формы.
- Токен хранится в зашифрованном хранилище устройства (`expo-secure-store`).
- При запуске сессия восстанавливается автоматически через `/auth/me`.
- Экраны защищены через `Stack.Protected` из Expo Router: без входа доступны только вход и регистрация.

### Роли
- Две роли: **admin** и **user**.
- Роль проверяется на сервере: любой изменяющий запрос к каталогу (`/manhwa`, `/collections`, `/cards`, `/upload`) от обычного пользователя получает `403`. Роль берётся из подписанного токена, поэтому подделать её нельзя. Скрытые кнопки на клиенте — только для удобства.
- При регистрации роль всегда «user», поле `role` из запроса игнорируется.
- Только администратору видны и доступны:
  - создание нового тайтла;
  - создание новой коллекции: указываются число карточек (1–32) и дата выхода в формате `ГГГГ-ММ-ДД`;
  - массовая загрузка изображений карточек в коллекцию. Счётчик показывает `выбрано / свободно`, и больше свободных слотов выбрать нельзя.

### Загрузка изображений
- Изображения выбираются из галереи (`expo-image-picker`), можно выбрать сразу несколько. Повторно выбранные картинки отсеиваются.
- Перед отправкой картинки уменьшаются до ширины 1080px (маленькие не увеличиваются) и сжимаются в JPEG (`expo-image-manipulator`).
- Файлы отправляются на сервер multipart-запросом с токеном и сохраняются в `public/images/uploads/`.
- Загруженная картинка сразу убирается из очереди. Если загрузка прервалась, повторное нажатие догрузит оставшиеся.
- Если коллекция уже заполнена, сервер отвечает `409`, а приложение сообщает, что остальные картинки не загрузятся.

### Офлайн-режим
- Состояние сети из NetInfo передаётся в `onlineManager` TanStack Query: без сети запросы ставятся на паузу и продолжаются, когда сеть появится.
- Состояние приложения из `AppState` передаётся в `focusManager`: при возврате в приложение устаревшие данные перезапрашиваются.
- Если при запуске `/auth/me` не ответил по причине, отличной от `401`, токен не удаляется. Показывается экран `OfflineScreen` с кнопкой **Reconnect**.
- На экране, где данных ещё нет, а сети тоже нет, показывается заглушка «No connection». При ошибке запроса показывается кнопка **Refresh**.

### Дизайн-система
- Собственная система тем: светлая и тёмная тема, начальная берётся из системной.
- Дизайн-токены (`colors`, `spacing`, `radius`, `gaps`, `typography`) собраны в `src/design-system`.
- Стили задаются фабриками `createStyles(theme)`, которые пересчитываются при смене темы.
- Тема передаётся и в навигацию Expo Router, поэтому фон при переходах между экранами не мигает белым.

## Технические детали

### Защищённые запросы
- Каждый запрос к API, кроме логина, требует JWT: сервер без валидного токена отвечает `401`.
- Токен автоматически подставляется в заголовок `Authorization: Bearer ...` через request-интерсептор axios, поэтому в коде запросов о нём думать не нужно.
- Загрузка файлов идёт мимо axios (через `expo-file-system`), поэтому токен и ответ `401` там обрабатываются отдельно.

### Обработка ошибок
- Все запросы проходят через одну функцию `apiFetch`, которая превращает ошибки axios в собственный класс `ApiError` со статусом и телом ответа. Остальной код работает с одним понятным типом ошибки.
- Ответ `401` (токен истёк или недействителен) ловит response-интерсептор: он удаляет токен, разлогинивает пользователя и очищает кэш данных. Пользователь попадает на экран логина.
- Если не задан адрес API (`EXPO_PUBLIC_API_URL`), приложение сразу сообщает об этом понятной ошибкой.
- Неудачные запросы TanStack Query повторяет до 2 раз.
- Ошибки рендера ловит `ErrorBoundary` (`src/components/error-screen`). Он подключён в корневом `_layout` и на экране коллекции. Кнопка **Back** возвращает на предыдущий экран, а если возвращаться некуда, экран рисуется заново.
- У авторизации есть явный статус: `loading` / `authenticated` / `unauthenticated` / `offline`.

### Безопасность и валидация на сервере
- `POST /auth/register`: логин 3–20 символов (латиница, цифры, `_`), имя 1–50, пароль 6–72 (ограничение bcrypt). Пароль хранится только как bcrypt-хэш.
- `POST /collections` требует `releaseDate` в формате `ГГГГ-ММ-ДД`, иначе `400`.
- `POST /cards` проверяет, что коллекция существует, назначает номер карточки и не даёт превысить лимит `cards` (`409`).
- Allow-list: запрещены `_embed`/`_expand` и пути глубже двух сегментов. Встроенные вложенные маршруты json-server (`/manhwa/1/userCards`) обходили проверки и отдавали чужие данные, включая хэши паролей.
- Пользователь всегда отдаётся без `passwordHash`.

### Работа с данными
- Все запросы и мутации оформлены как хуки в `src/api/queries/` (`useManhwas`, `useCollectionById`, `useCollectionCards`, `useUserCards`, `useAddUserCard` и т. д.). Экраны не обращаются к API напрямую.
- Данные кэшируются (свежими считаются 60 секунд), а после успешной мутации нужный кэш инвалидируется и данные перезапрашиваются.
- Zod-схемы форм вынесены в `src/schemas/` (`auth`, `manhwa`, `collection`).

```
src/
├── app/                         # экраны (Expo Router)
│   ├── (auth)/                  # вход и регистрация
│   └── (main)/
│       ├── (tabs)/
│       │   ├── (catalog)/       # вкладка «Каталог»
│       │   ├── (mine)/          # вкладка «Мои коллекции»
│       │   ├── (catalog,mine)/  # общие экраны обеих вкладок: тайтл → коллекция → карточки
│       │   └── profile.tsx
│       └── manhwa/              # админские формы создания
├── api/
│   ├── queries/         # хуки useQuery / useMutation
│   ├── axios-instance   # axios + интерсепторы токена и 401
│   ├── client           # apiFetch, ApiError, resolveImageUrl
│   ├── auth             # login / me / logout
│   ├── token-storage    # работа с SecureStore
│   └── upload           # загрузка изображений
├── components/          # переиспользуемые компоненты, error-screen, offline-screen
├── design-system/       # токены и стили экранов
├── hooks/               # useAuth, useTheme, useImagePicker, useRefresh
├── providers/           # AuthProvider, ThemeProvider
├── schemas/             # zod-схемы форм
└── types/               # доменные типы
server/
├── mock-server.js       # json-server + JWT-авторизация + загрузка файлов
├── db.json              # данные
└── package.json         # зависимости mock-сервера
```

Модель данных: **manhwa** → **collections** → **cards**. У коллекции есть `releaseDate` (порядок сортировки) и `cards` (максимальное число карточек). Владение карточкой хранится в `userCards` (`userId`, `collectionId`, `manhwaId`, `cardId`, `count`), не больше одной строки на пару «пользователь + карточка».

## Запуск

### 1. Зависимости
У приложения и mock-сервера отдельные `package.json`, поэтому зависимости ставятся в двух местах:
```bash
npm install                  # приложение
npm --prefix server install  # mock-сервер (json-server, jsonwebtoken, bcryptjs, multer)
```
Без второй команды `npm run api` упадёт с `Cannot find module 'json-server'`.

### 2. Переменные окружения

**`.env`** в корне (скопировать из `.env.example`):
```
EXPO_PUBLIC_API_URL=http://<IP-компьютера-в-локальной-сети>:3001
```
Нужен именно LAN IP, а не `localhost`: телефон или эмулятор не видит `localhost` компьютера. Узнать IP можно командой `ipconfig` (Windows) или `ifconfig` (macOS/Linux).

**`server/.env`**:
```
JWT_SECRET=любая-длинная-случайная-строка
```

### 3. Бэкенд
```bash
npm run api
```
Сервер запустится на порту `3001`.

### 4. Приложение
```bash
npm start
```
Дальше открыть в Expo Go, эмуляторе или браузере (`npm run android` / `ios` / `web`).

## Текущие ограничения
- Бэкенд пока mock-сервер на json-server.
- Редактирования и удаления тайтлов, коллекций и карточек в приложении нет, они правятся в `db.json`.
- Профиль пока заглушка: подписки и подписчики не работают, аватара нет.
- Refresh-токенов нет, access-токен живёт 7 дней.
- Пагинации нет: каталог загружается целиком.
- Язык интерфейса смешанный (русский и английский).

## Планы
- Контракт API по mock-серверу.
- Полноценный бэкенд с базой данных и хранилищем изображений.
- Профиль: статистика, редактирование, удаление аккаунта.
- Вход через Google.
- Редактирование и удаление каталога из приложения.
